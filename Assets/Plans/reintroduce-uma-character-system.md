# Project Overview
- **Game Title**: Zombera
- **High-Level Concept**: Survival RPG with character customization, base building, and tactical combat.
- **Players**: Single player (with squad management features).
- **Target Platform**: PC (Standalone Windows 64).
- **Render Pipeline**: Universal Render Pipeline (URP).
- **Main Character System**: Reintroducing UMA (Unity Multipurpose Avatar) as the core character system to replace the current manual bone/mesh manipulation system.

# Game Mechanics
## Core Gameplay Loop
The player creates a character, scavenges for resources, builds a base, and survives against zombies. Character appearance is a key part of identity and progression (equipment/clothing visuals).

## Controls and Input Methods
New Input System is used. Movement and combat rely on the character rig. UMA provides a standard Humanoid rig compatible with existing animations.

# UI
- **Character Creator**: The existing UGUI-based character creator will be updated to drive UMA DNA and Wardrobe.
- **HUD**: Squad portraits and unit displays will use the visuals generated by UMA.

# Key Asset & Context
- `CharacterAppearanceProfile.cs`: Data structure for saving/loading appearance. Needs to be expanded for UMA.
- `AppearanceProfileService.cs`: The service that applies/captures visuals. Currently manual; needs to be UMA-powered.
- `CharacterWardrobeSelection.cs`: Needs to support more than just Hair/Beard to leverage UMA's full power.
- `Player.prefab`: Needs `DynamicCharacterAvatar` and related UMA components.

# Implementation Steps
## 1. Data Structure Expansion
- **File**: `Assets/Scripts/UI/Menus/CharacterCreation/CharacterWardrobeSelection.cs`
- **Change**: Change from fixed `hairRecipeName`/`beardRecipeName` to a list of `WardrobeEntry` (slot name + recipe name) to support all UMA slots.
- **File**: `Assets/Scripts/UI/Menus/CharacterCreation/CharacterAppearanceProfile.cs`
- **Change**: Ensure `Sanitize()` handles the new wardrobe list.

## 2. UMA Service Implementation
- **File**: `Assets/Scripts/UI/Menus/CharacterCreation/AppearanceProfileService.cs`
- **Change**:
    - Import `UMA` and `UMA.CharacterSystem`.
    - Rewrite `TryApplyProfile` to:
        1. Get `DynamicCharacterAvatar`.
        2. Call `ChangeRace(profile.raceName)`.
        3. Iterate through `profile.bodyValues` and apply to `avatar.GetElement("DNA")`.
        4. Clear existing wardrobe and apply all recipes from `profile.wardrobeSelection`.
        5. Set colors (Skin, Hair, Eyes) via `avatar.SetColor`.
        6. Call `avatar.BuildCharacter()`.
    - Rewrite `TryCaptureProfile` to read these values back from a built UMA avatar.

## 3. Prefab Update
- **Asset**: `Assets/Prefabs/Player/Player.prefab`
- **Change**:
    - Add `DynamicCharacterAvatar` component.
    - Add `UMAData`, `UMADna` (if not auto-added).
    - Configure the `CharacterGenerator` and `Context` (likely pointing to global UMA assets).
    - Ensure `Animator` is correctly linked to the UMA generated rig.

## 4. UI Controller Integration
- **File**: `Assets/Scripts/UI/Menus/CharacterCreation/CharacterCreatorCustomizationController.cs`
- **Change**:
    - Update the preview logic to wait for UMA's `onCharacterCreated` event before allowing certain interactions or updating the camera.
    - Ensure wardrobe selection UI correctly populates the expanded wardrobe list in the profile.

## 5. Spawning & Persistence
- **File**: `Assets/Scripts/Characters/PlayerSpawner.cs`
- **Change**: Ensure the spawner waits for the UMA avatar to finish building before enabling physics or input (avoiding the "t-pose" or "half-built" frame).

# Verification & Testing
1. **Manual Check**: Open the Character Creator from the Main Menu.
2. **Customization Test**: Verify that sliders correctly change the UMA character's body shape and that wardrobe picks (Hair, Beard, etc.) swap correctly.
3. **Persistence Test**: Confirm that clicking "Confirm" saves the profile and that loading into the World scene reproduces the exact same UMA character.
4. **Combat Test**: Verify that the UMA-generated rig correctly plays animations and receives damage (links to `UnitHealth` and `UnitController`).
